Core mental model
R → A → G
Retrieve relevant knowledge → Augment the prompt → Generate a grounded answer.
Key idea: chunking + embedding usually happen before the user's question, during indexing.

In production, this stage can also extract metadata such as document title, author, date, business unit, security classification, and source URL.
2

Chunk documents

Split large sources into retrievable passages. Chunk size and overlap affect recall and precision.

3

Create embeddings + index

Convert chunks into numerical vectors and store them with metadata in a searchable index.

Chunk text
→
Embedding model
→
Vector + metadata
→
Vector DB
Important: this is normally an offline/indexing step. You do not usually re-chunk and re-embed the whole knowledge base for every user query.
4

Embed / understand the query

The user's question is represented so it can be compared with indexed knowledge.

5

Retrieve Top-K chunks

Search for the most relevant passages using semantic similarity, keyword matching, or both.

6

Rerank retrieved context

A reranker can reorder candidate chunks using a stronger relevance model.

7

Augment the prompt

Insert retrieved context alongside instructions and the user's question.

8

Generate grounded answer

The LLM answers using the supplied context instead of relying only on model memory.

9

Evaluate the RAG system

Good RAG is not just “did the LLM respond?” Measure retrieval and answer quality.

—Retrieval relevance
—Groundedness
—Context efficiency
—Hallucination risk
Production teams also evaluate latency, cost, citation accuracy, security filtering, freshness, recall@K, precision@K, answer faithfulness, and user satisfaction.
